## 1. 验收目标

用真实业务语料回答两个问题：

1. **功能可用性**：这些书能不能通过产品界面完成入库、分块、检索、引用与拒答的全流程；
2. **质量可用性**：在真实长文档上，答案是否准确、来源是否可定位、资料未覆盖时是否敢说"不知道"。

不在本轮范围（属规划能力，看到"不支持"是预期）：ES/LightRAG/Web 检索通道、MinerU 批量解析、
图片与扫描件 OCR、EPUB 解析。

另外两条硬约束（决定了验收必须分阶段）：

| 约束 | 值 | 影响 |
|---|---|---|
| 前端 Nginx 单请求上限 | `client_max_body_size 100m` | 192MB 的 PDF 会在代理层被拒（413），到不了 API |
| 解析器支持格式 | `.md/.txt/.csv/.xlsx/.pdf/.html/.json/.xml` | `.epub`、`.docx`、图片会被上传前置拦截 |

复现预检（检查任意 PDF 有没有文字层，这是入库能否成功的第一判据）：

```bash
.venv/bin/python - <<'PY'
from pypdf import PdfReader
p = "/Users/wangtongzhou/Documents/育儿/崔玉涛自然养育法.pdf"
r = PdfReader(p)
print("pages:", len(r.pages))
print("p40 chars:", len(r.pages[40].extract_text() or ""))
PY
```

输出每页字符数若持续为 0，说明是扫描件：当前产品会解析出空内容，分块阶段失败。

### 2.1 本机解析分块模拟（已执行，不消耗模型调用）

用产品自身的解析器与分块服务对《崔玉涛自然养育法》跑了 dry-run：

| 指标 | 实测值 |
|---|---|
| MIME 识别 | `application/pdf` |
| Block 数 | 272（全部是 `ParagraphBlock`，**没有 `HeadingBlock`**） |
| Chunk 数 | 272（约等于"一页一块"） |
| 总字符数 | 155,160 |
| 块长度 p10 / p50 / p90 | 192 / 620 / 788 字符 |
| 带章节路径的 chunk | **0 / 272** |

由此得到两条必须提前知道的判定修正：

1. **章节路径为空是当前实现的必然结果**：PDF 解析器按页产出纯段落 Block，不识别标题层级，
   而章节路径由 `HeadingBlock` 驱动。所以验收时不要把它当缺陷重复上报，作为已知限制记录即可；
   但要指出它对召回粒度的影响（见下一条）。
2. **一页一块的粒度**：页文本普遍小于 1024 字预算，因此不会二次切分；跨页连续的主题会被切在
   页边界上，检索时可能只召回半段论述。观察方式：问一个跨页论述的问题（如 Q1、Q5），
   看 Trace 是否召回了相邻两页。

## 12. 风险与已知边界

| 风险 | 说明 | 缓解 |
|---|---|---|
| 扫描版 PDF | 无文字层，解析为空导致分块失败 | 入库前先做文字层预检（§2 脚本）；长期需接 OCR/MinerU |
| EPUB | 不在解析器支持列表 | 先转 `.md`/`.txt` 再入库 |
| >100MB 文件 | Nginx 单请求上限 | 拆分文件或提高 `client_max_body_size` 并评估内存 |
| 长文档耗时与费用 | 296 页≈数百 chunk，1054 页≈上千 chunk | 分阶段导入，先小后大；关注模型配额 |
| 中文 PDF 断行噪声 | 影响 chunk 语义与召回 | 用 §5 的 S3/S4 检查，必要时调整分块预算 |
| 拒答阈值 | `rag.rerank.min_score=0.4` 决定"敢不敢答" | 调低会更敢答但更易编造，调整后需重跑无答案集 |
