# 人工验收方案（页面访问与使用）

## 1. 验收对象与边界

验收对象：本机 Docker Compose 全栈部署（`postgres` / `redis` / `mcp` / `api` / `worker` /
`frontend`）以及 React 前端全部页面。

> 如果你要验收的是真实业务语料（`/Users/wangtongzhou/Documents/育儿`），请改用
> `12-育儿语料人工验收执行方案.md`：它是本文的语料版执行手册，包含预检结论、题库与边界取证。

覆盖范围：登录与权限、问答主链路、知识库/文档/Chunk、意图树、查询词映射、RAG Trace、
检索质量实验台、Pipeline 与任务、智能体与 Prompt、MCP 管理与调试、运行时与模型设置、
用户与审计、系统概览、响应式与深链恢复。

**本次不覆盖的项**（属于规划中的后续能力，看到"没有"不要记为缺陷）：

| 项 | 现状 | 表现 |
|---|---|---|
| ES 关键词通道 | `rag.keyword.type=none` | Trace 的 keyword 通道为空 |
| LightRAG 图谱通道 | `rag.graph.type=none` | Trace 的 graph 通道为空 |
| Web / You.com 检索 | 未实现 | 无该配置项，MCP 工具里也没有 `youcom_search` |
| MinerU / 图片 VLM 解析 | 未实现 | 当前只支持 `.md`/`.txt`/`.csv`/`.xlsx`/`.pdf`/`.html`/`.json`/`.xml`；`.docx`/`.pptx`/`.xls`/`.rtf`/图片会被前置拦截 |
| Enhancer / Enricher 节点 | 未实现 | Pipeline 编排里没有增强节点类型 |
| 远程定时刷新 | 仅预留 DB 字段 | 文档表单里没有可用的定时刷新入口 |

判定基线有一条必须记住：后端全部返回 `Result<T>` 包装，**未登录、无权限等业务错误也返回
HTTP 200**，只有 `code` 字段才说明结果。例如未登录是 `{"code":"40100"}`，无权限是
`{"code":"40300"}`。验收时不要只看 HTTP 状态码。

## 3. 第 0 步：让页面真正可用（必做）

**为什么必须做这一步**：前端路由守卫 `RequireAuth` 在没有 token 时会直接跳 `/login`，而
后端 `auth.enabled=false` 时 `POST /auth/login` 会返回"认证尚未启用"。也就是说当前
`auth=false` 的栈只能通过接口自测，不能做页面验收。

顺序不能颠倒：先在"认证关闭"状态下创建管理员，再打开认证开关。

### 3.1 创建管理员（认证仍关闭时执行）

```bash
curl -s -X POST http://127.0.0.1:9090/api/ragent/users \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"<你的强密码>","role":"ADMIN"}'
```

期望返回 `{"code":"0","message":"ok","data":"<userId>"}`。密码建议 12 位以上并含大小写与符号。

### 3.2 写入部署配置 `.env.docker`

`.env.docker` 已在 `.gitignore` 内，不会入库；它同时供 compose 变量替换与容器注入使用。
两个中间件密码必须与当前栈保持一致（容器卷已按这两个值初始化，改了会导致连不上库）：

```dotenv
COMPOSE_PROJECT_NAME=ragent
RAGENT_IMAGE_TAG=local

POSTGRES_DB=ragagent
POSTGRES_USER=postgres
POSTGRES_PASSWORD=replace-with-a-strong-postgres-password
POSTGRES_PORT=15432

REDIS_PASSWORD=replace-with-a-strong-redis-password
REDIS_PORT=16379

API_PORT=9090
FRONTEND_PORT=5173

# 认证：先建管理员再置 true
RAGENT_AUTH_ENABLED=true
JWT_SECRET=<粘贴 openssl rand -hex 32 的输出>

# 评测与模型：验收要用到评测页和问答
RAGENT_EVAL_ENABLED=true
BAILIAN_API_KEY=<从 .env 的 RAGENT_AI__PROVIDERS__BAILIAN__API_KEY 复制>
```

生成密钥并复制模型 Key：

```bash
openssl rand -hex 32
grep '^RAGENT_AI__PROVIDERS__BAILIAN__API_KEY=' .env
```

### 3.3 重建 API 与 Worker 使配置生效

```bash
docker compose --env-file .env.docker up -d --force-recreate api worker --wait
```

### 3.4 验证登录与权限

```bash
BASE=http://127.0.0.1:9090/api/ragent
curl -s -X POST $BASE/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"<你的强密码>"}'       # 期望 code=0 且拿到 token
curl -s $BASE/admin/dashboard/overview                        # 期望 code=40100（未登录）
```

然后浏览器打开 `http://127.0.0.1:5173/`，应跳到登录页；用该账号登录后进入 `/chat`。

注意：`JWT_SECRET` 变更会让所有已签发 token 失效（表现为操作中途跳回登录页）；
`docker compose down -v` 会清空数据库，管理员与知识库都会消失，需要重做 3.1 与语料播种。

## 5. 测试方法与证据规范

1. 浏览器用 Chrome 或 Edge，DevTools 常开 **Console** 与 **Network**（筛选 Fetch/XHR，聊天页再加
   EventStream）；目标：无红色报错、请求体 `code=0`。
2. 每个页面至少走三态：加载态、正常态、空态/错误态（例如搜索一个不存在的关键词）。
3. 证据留存：截图命名 `批次-页面-序号.png`（如 `C-文档工作台-03.png`）；问题记录里附上
   响应体的 `requestId`（后端日志可精确定位）与聊天/检索产生的 `traceId`。
4. 无法复现时记录操作时间点与完整请求响应，不要只写"报错了"。

## 9. 已知非缺陷（预期行为，别记为问题）

| 现象 | 解释 |
|---|---|
| 未登录返回 HTTP 200 但 `code=40100` | `Result<T>` 契约，业务错误统一走响应体 |
| Trace 里只有 vector 通道 | ES / LightRAG / Web 通道未实现 |
| 评测页入口不存在 | 仅在 `RAGENT_EVAL_ENABLED=true` 时挂载路由 |
| 删除文档后列表短暂仍显示 | 文档与知识库删除是异步清理任务 |
| 知识库有文档时无法删除 | 需先清空文档（异步完成后再删库） |
| 运行时页只显示一个 Provider | 只有百炼配置了 API Key，其余 provider 未配置 |
| 提问首次响应较慢 | 改写/意图走模型 FAST 档，冷启动首包更明显 |
| MCP 调试只能用页面 | `mcp:9099` 不映射宿主端口，属安全基线 |
| 上传大文件被拒绝 | Nginx 单请求上限 100MB |
