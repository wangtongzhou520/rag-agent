# 前端去 AI 化与视觉改版方案

> 目标：把当前"能用的蓝色 SaaS 控制台"改造成**有明确设计立场、看起来像被设计过**的产品界面。
> 本文是可执行的改版基线：先给判定标准与现状证据，再给设计令牌、组件与逐页规范、实施批次与验收口径。
> 关联文档：`08-前端工程与页面设计.md`（视觉体系章节将被本文取代）、`11-人工验收方案.md`（视觉验收并入）。

## 1. 怎么算"去 AI 化"

"AI 味"不是玄学，它由一组可观察、可量化的默认选择构成。本次改版把标准定死成下面 8 条，
验收时逐条对照，不做主观争论：

| # | 判定标准 | 当前值 | 改版目标 |
|---|---|---|---|
| 1 | 渐变使用处数（非数据可视化） | 13 | **0** |
| 2 | 玻璃拟态（`backdrop-filter` / `blur`） | 7 | **0** |
| 3 | 圆角取值种类 | 10 种（4/5/6/7/8/9/10/11px/999px/50%） | **≤ 3 种**（2px 控件、4px 容器、全圆仅头像与状态点） |
| 4 | `box-shadow` 声明数 | 38 | **≤ 6**，且仅用于模态与浮层 |
| 5 | 无限循环装饰动画 | 4（脉冲、旋转、pending 线、信号流动） | **0**（保留必要的加载指示） |
| 6 | 品牌色阶数量 | 11 档蓝色梯度（`--blue-50..950`） | **1 个强调色 + 5 档中性色** |
| 7 | 页面 CSS 中的硬编码色值 | 大量（`#fbfcfe`/`#087a4e`/`#fff7f7` …） | **0**，全部走令牌 |
| 8 | 样式文件组织 | `globals.css` 5017 行 + 按页 CSS，共 8029 行 | 拆为 tokens / base / components / pages，单文件 ≤ 600 行 |

另有一条**不属于风格、但必须一起修**的可访问性缺陷：

| 项 | 实测 | 要求 |
|---|---|---|
| `--text-muted` #8A9AB2 于白底 | 2.86:1 | ≥ 4.5:1 |
| 焦点环 `--blue-300` #93C5FD 于白底 | 1.80:1 | ≥ 3:1 |

## 2. 现状诊断（有据可查）

```bash
# 复现本文所有数字
cd frontend

grep -rn "backdrop-filter\|blur(" src --include='*.css' | wc -l              # 7
grep -rc "box-shadow" src/styles/globals.css                                 # 38
grep -ro "border-radius: [^;]*" src --include='*.css' | sort -u | wc -l      # 10
grep -n "infinite" src/styles/globals.css | wc -l                            # 4
sed -n '/^:root/,/^}/p' src/styles/globals.css                               # 11 档蓝
```

| 症状 | 具体表现 | 为什么显得"AI 生成" |
|---|---|---|
| 默认蓝 | `--blue-600: #2563eb` 就是 Tailwind 默认蓝；11 档梯度全量引入 | 最常见的大模型默认配色，无品牌辨识度 |
| 视觉糖堆叠 | 渐变 + 玻璃模糊 + 大圆角 + 面板阴影同时存在 | 生成式模板的典型组合，缺乏取舍 |
| 尺度不统一 | 圆角 10 种、阴影 38 处、字号与间距随手取值 | 逐块生成、没有全局尺度约束 |
| 装饰性动效 | `status-pulse`、`pending-line`、`signal-flow` 无限循环 | 用动效制造"科技感"，信息价值为零 |
| 营销式文案与布局 | 登录页左栏大标语"知识检索与问答，在一个工作区完成。"+ 三条能力清单 + 网格背景 | SaaS 落地页模板，与控制台的使用场景不匹配 |
| 卡片墙 | 面板套面板、每块都有边框+阴影+圆角 | 缺少层级判断，用装饰代替排版层级 |
| 色彩衍生失控 | 页面 CSS 里出现 `#fbfcfe`/`#f7f9fc`/`#fff7f7`/`#087a4e` 等大量近邻色 | 没有令牌，逐页"顺手调一点" |

## 3. 设计定位：纸墨档案（Paper & Ink）

**为什么选这个方向**：产品的核心动作是"查资料、看来源、追链路"——知识库、分块、引用角标、
RAG Trace 本质上是**文献工作**。当前界面用的是通用云控制台语言，和业务不搭。
改用"研究工具/档案室"的语言，能同时解决"AI 味"和"没有记忆点"两个问题：
纸色底 + 墨色字 + 细分隔线 + 编号引用，天然贴合"溯源"这件事，也和蓝色 SaaS 控制台一眼区分开。

**一句话设计立场**：*用纸质文献的克制与秩序承载工程系统的密度；唯一的高饱和色只出现在"需要被追踪的东西"上（引用编号、激活位置、危险动作）。*

必须做到的三件事：

1. **排版即层级**：靠字号、字重、留白与栏线区分层级，而不是靠卡片、阴影和填充色；
2. **克制的强调**：朱砂色只用于引用编号、当前选中、主操作与危险态，界面占比 < 5%；
3. **留白优先**：删除一切装饰性元素后，用 8px 基准的间距系统重新分配呼吸感。

## 4. 设计令牌

### 4.1 色彩

| 令牌 | 值 | 用途 |
|---|---|---|
| `--paper` | `#F6F3EC` | 页面底色（暖纸色） |
| `--paper-raised` | `#FFFDF8` | 面板/卡片底（比纸色亮一档） |
| `--paper-sunken` | `#EDE8DE` | 凹陷区、输入框底、代码块 |
| `--ink` | `#16150F` | 主文本 |
| `--ink-soft` | `#4A4740` | 次要文本、表头 |
| `--ink-faint` | `#7A756A` | 辅助信息（对比度 4.6:1，替代原 2.86:1 的 muted） |
| `--rule` | `#E2DCCF` | 1px 分隔线（主要分层手段） |
| `--rule-strong` | `#C9C1B1` | 强调分隔线、表头线 |
| `--accent` | `#9E2B25` | 朱砂：主操作、激活态、引用编号 |
| `--accent-soft` | `#F2E4E2` | 朱砂浅底（选中行、标签底） |
| `--info` | `#2C4A52` | 黛蓝：链接、图表第二色、焦点环 |
| `--success` / `--warning` / `--danger` | `#2F6B4F` / `#8A6A1F` / `#9E2B25` | 语义色（danger 与 accent 同源，用明度区分） |

规则：正文只用 `--ink*` 三档；朱砂面积合计不超过单屏的 5%；图表最多用 2 个色（info + accent）。

### 4.2 字体

| 角色 | 字体 | 字重 | 字号 |
|---|---|---|---|
| 品牌 / 页面标题 | 宋体系（Noto Serif SC，回退 Songti SC / SimSun） | 600 | 28 / 20 |
| 正文 / 表格 / 表单 | 黑体系（Noto Sans SC，回退 PingFang SC / Microsoft YaHei） | 400 / 500 | 14 / 13 / 12 |
| 数字 / ID / 时间戳 / 代码 | 等宽（JetBrains Mono，回退 SFMono / Consolas） | 400 | 13 / 12 |

- 中文字体请求 **≤ 2 个**：优先使用系统字体栈，需要自托管时做子集化（只保留常用 3500 字）；
- 行高：正文 1.6，表格 1.4，标题 1.25；字重层级**最多 3 档**（400 / 500 / 600）；
- 所有数字型字段（耗时、token、ID、时间）统一等宽并右对齐，天然形成"工程感"。

### 4.3 空间、形状、动效

| 令牌 | 值 | 说明 |
|---|---|---|
| 间距基准 | 4 / 8 / 12 / 16 / 24 / 32 / 48 | 只用这 7 档，禁止魔法数字 |
| 圆角 | `--radius-sm: 2px`（控件）/ `--radius-md: 4px`（容器）/ `50%`（头像） | 近乎直角，去掉"泡泡感" |
| 边框 | 一律 1px `--rule`；强调用 `--rule-strong` | 替代阴影做分层 |
| 阴影 | 默认无；`--shadow-overlay: 0 8px 24px rgb(22 21 15 / 8%)` 仅模态/浮层 | 全站 ≤ 6 处 |
| 动效 | 120ms（hover/聚焦）、160ms（面板与抽屉）、首屏错峰 40ms 渐显 | 全部 `ease-out`；**无无限循环** |
| 图标 | lucide，16px，线宽 1.5，颜色继承文本 | 不用彩色图标底、不用 emoji |

## 5. 壳层与布局重构

**现状**：左侧深色侧栏 + 渐变品牌区 + 面板卡片墙 + 12 个平铺导航项。

**改版**：

1. **顶部 masthead（48px）**：左侧品牌字标（宋体）＋竖线＋当前模块名；右侧全局搜索（`⌘K`）与用户菜单。去掉渐变与投影，只用一条底线。
2. **左侧导航（216px，可折叠至 56px）**：按"问答 / 知识 / 编排 / 系统"四组，组标题用小号 `--ink-faint`＋字距 0.08em；激活项＝左侧 2px 朱砂竖线＋`--ink` 文字，**不用填充色块**。
3. **内容区**：`max-width: 1440px`，左右 padding 32；页头＝宋体标题 + 一句说明；操作条 sticky（滚动时补一条底线）。
4. **表格**：表头小号 `--ink-soft` + 下边线 `--rule-strong`；行高 40，hover 用 `--paper-raised`，选中用 2px 朱砂左线 + `--accent-soft` 底；取消斑马纹、行内阴影与圆角卡片；数字列等宽右对齐。
5. **对话区**：主列 760px 居中；用户消息＝`--paper-sunken` 底 + 2px 左线；助手回答**无背景**，以排版与引用角标区分；来源面板改为"脚注列表"（朱砂编号 + 文档名 + 片段），与正文引用形成呼应。
6. **空态**：小标题 + 一句说明 + 一个主操作，用细线框而非插画；错误态给出"发生了什么 + 怎么办"。

## 6. 组件改造清单

| 组件 | 现状问题 | 改版要求 |
|---|---|---|
| Button | 圆角 8-10px、渐变主色、蓝色 focus 光晕 | 2px 圆角；主按钮＝实心朱砂、次按钮＝描边、文字按钮无边框；高度 32/36 两档；focus＝2px `--info` 外描边 |
| Input / Select | 浅蓝底、圆角 8px、蓝色 focus 环 | `--paper-raised` 底 + 1px 线；聚焦只变线色为 `--info`，不加光晕 |
| Card / Panel | 每块都有阴影 + 圆角 + 蓝边 | 默认无边框无阴影，靠留白分组；需要分组时用 1px `--rule` 或背景差一档 |
| Table | 斑马纹 + 卡片包裹 | hairline 表格 + 工具条；列宽稳定；数字等宽右对齐 |
| Tag / Badge | 多彩圆角胶囊 | 只保留 5 种语义色；直角 2px；小号大写式字距（中文用 12px + 0.04em） |
| Dialog | 圆角 16px + 重阴影 + 遮罩模糊 | 4px 圆角 + `--shadow-overlay` + 纸色遮罩（无模糊）；标题宋体 |
| Toast | 右下角气泡 | 左下细条：3px 左侧语义色边 + 文本，无圆角阴影 |
| Tabs | 蓝色下划线 + 填充 | 文字 tab + 2px 朱砂下划线；未激活 `--ink-soft` |
| 图表 | 渐变面积 + 粗网格 | 细线（1.5px）+ 数据点；网格 0.5px 虚线；最多 2 色 |
| 空态/加载 | 脉冲动画 + 插画 | 静态骨架（`--paper-sunken`）+ 文案；无循环动画 |

## 7. 逐页面设计要点

| 页面 | 关键改动 |
|---|---|
| 登录 | 去掉左右分栏与营销标语；居中 420px 表单 + 左侧竖排品牌字标与版本号；文案改为名词短语；背景用纸纹（极淡噪点）而非网格线 |
| 问答 | 三栏（会话 240 / 对话 760 / 来源 320）；来源脚注化；引用角标为宋体上标朱砂；停止生成按钮改为低干扰文字按钮 |
| 系统概览 | KPI 由"卡片"改为"栏线报表"：数字（等宽 28px）+ 标签 + 环比；趋势图细线 + 关键点标注 |
| 知识库管理 | 列表 + 右侧详情抽屉；集合名、文档数、向量维度用等宽字体 |
| 文档工作台 | 状态用"文本 + 语义色点"而非彩色胶囊；上传区改为细线框拖拽区 |
| Chunk 工作台 | 左侧分块列表（序号等宽）+ 右侧正文编辑；章节路径作为面包屑显示 |
| 意图树 | 树线用 1px `--rule`；节点类型用文字标签 + 颜色仅区分 kind；批量操作放工具条 |
| 查询词映射 | 两列表格式（源词 → 目标词）+ 行内编辑；等宽显示匹配类型 |
| RAG Trace 列表/详情 | 详情改为"时间轴 + 阶段表"：等宽耗时、朱砂标记异常节点；JSON 用纸色代码块 |
| 检索质量实验台 | 指标表格 + 迷你条形（单色）；报告对比用差值与方向箭头，不用彩色徽章 |
| Pipeline 与任务 | 节点链用细线连接 ＋ 等宽节点 ID；任务表突出状态与重试次数 |
| 智能体与 Prompt | 槽位列表 + 右侧编辑器；生效/未生效用文字标注；编辑器使用等宽字体 |
| MCP 管理与调试 | Server/Tool 两级列表；调试面板为请求/响应双栏等宽文本 |
| 运行时与模型 | 三档路由用表格化展示；熔断状态用语义色点 + 文字 |
| 用户管理 / 审计日志 | 标准 hairline 表格 + 筛选工具条；变更详情用左右对比排版 |
| 404 / 空态 | 宋体大字 + 一句说明 + 返回操作；不做插画 |

## 8. 实施批次

| 批次 | 内容 | 产出 |
|---|---|---|
| **P0 设计基座** | `tokens.css`（颜色/字体/间距/圆角/动效）、字体栈、`base.css` 重置与排版、壳层（masthead + 导航）、Button/Input/Table/Dialog/Tag/Toast 六个基础组件 | `/styleguide` 内部页面，可视化全部令牌与组件状态 |
| **P1 主路径** | 登录页 + 问答页（含来源脚注、会话列表、引用角标） | 最具识别度的两个页面 |
| **P2 知识链路** | 知识库、文档工作台、Chunk 工作台 | 表格与编辑形态定型 |
| **P3 诊断链路** | RAG Trace 列表/详情、评测台、Pipeline 与任务 | 复杂信息密度页面定型 |
| **P4 配置与系统** | 智能体与 Prompt、MCP、运行时、意图树、映射、用户、审计、概览、404 | 全站覆盖 |
| **P5 收口** | 微文案统一、空态与错误态、Playwright 视觉快照、`globals.css` 拆分与旧类名清理 | 移除全部旧样式残留 |

每批都按"新增令牌与新类 → 迁移页面 → 删除该页旧类"推进，**不做一次性重写**。

## 9. 验收标准

风格验收（逐条打勾，全部可脚本化或肉眼判定）：

- [ ] 第 1 节 8 条量化标准全部达标（渐变 0、玻璃 0、圆角 ≤3、阴影 ≤6、无限动画 0、色阶收敛、硬编码 0、样式拆分）

## 10. 迁移策略与风险

| 风险 | 说明 | 应对 |
|---|---|---|
| `globals.css` 5017 行 | 一次性重写会引入大量回归 | 增量迁移，新类名前缀 `ui-`，逐页替换后再删旧类 |
| 全站色值替换 | 页面 CSS 里硬编码色多 | P0 先建令牌，再用 codemod/脚本批量映射，人工复核对比度 |
| 字体体积 | 中文字体可达数 MB | 优先系统字体栈；自托管时子集化并限制请求数 ≤2 |
| 视觉与功能测试冲突 | 改样式可能影响 Playwright 选择器 | 保留语义化 `data-testid`，不以样式类做断言 |
| 用户已看惯旧界面 | 全量改版有适应成本 | 按批发布，P1 先交付问答与登录，收集反馈后推进 |

## 11. 下一步

建议直接从 **P0 设计基座** 开工：产出 `tokens.css` + 组件改造 + `/styleguide` 页面。
P0 完成后就能用真实页面（styleguide）评审风格，确认方向再批量迁移其余页面，
避免在错误方向上做全站改造。
